# S1-04 Thin Routes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make shell API routes thin controllers over application use cases while preserving the Phase 2 HTTP contract and safe error handling.

**Architecture:** `server/http/route.ts` owns authentication and HTTP error translation. Controllers parse HTTP-only inputs and call `container`; the application layer gains explicit full-list and legacy-summary use cases because the existing paginated list and rolling dashboard summary do not cover those public endpoints.

**Tech Stack:** Next.js route handlers, TypeScript, Zod 4, Vitest, Drizzle, Playwright.

**Spec:** `docs/phase-4/sprint-1-clean-architecture/04-thin-route-handlers.md`

## Global Constraints

- Routes do not import `@/db`, `drizzle-orm`, storage adapters, or the old `store`.
- Keep public status and body shapes, including 400/413 JSON errors, 422 flattened Zod issues, 201 create, 204 delete, CORS headers, and unpaginated GET.
- Unknown errors return only `{ error: 'Erro interno', requestId }`; full error stays in server logs.
- `auth/register` and NextAuth remain public; authenticated routes obtain `actor.userId` from the session.

## Review Focus

- Missing session must not call a use case.
- Invalid query and JSON bodies must not reach the repository and must preserve 422/400/413 shapes.
- Unpaginated list must return all records, even above the 100-item pagination limit.
- Summary date range and transfer handling must match the existing endpoint.
- Attachment upload must validate ownership, type, size, and CORS without exposing storage internals.
